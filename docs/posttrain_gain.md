## 0. 一句话

③ 现在训的是"每层一个和路由无关的低秩项", 已经在编程判决份 Same top ≈ 84.8 封顶(加轮数、换料加料、秩翻倍三条杠杆 10-23 全试过, 一个点没动)。
本方案把 ③ 的可训参数换成"**每个专家 down 投影每个输出通道的增益**"(和 ② 同一种参数, 但不再层内闭式解, 改成整模型反传、直接向出厂原件蒸馏)。
引擎加载路一行不用改(③ 目录里放 `gr_Lnn.bin`, 引擎本来就把它和 ② 的增益逐元素相乘, core_v41_amp.c `v41_gr_load`), 体积 +42 MB(与 ② 的增益文件同大)。

## 1. 为什么是这个方向(先看账)

### 1.1 "别人同体积 94%"核实

查到的出处: [Mia-AiLab/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw](https://huggingface.co/Mia-AiLab/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw)。
- 体积 **210.6 GB**(我们 113.6 GB 的 1.85 倍): 路由专家 3 bit(18~22 层 2 bit), 注意力 5 bit, 共享专家 4~5 bit, 输出头 6 bit。
- 94.0% 是"闲聊"那一档的 top-1 一致率; 全部 100 段对话合起来 96.6%, 平均 KL 0.0137。教师强制逐位打分, 89,880 个答案位, 参照 = 原件。
- 页面没写任何训练 / 蒸馏, 只说"量化过程打了补丁", 补丁没公开。

结论: 不是同体积。我们的专家是 1.5~1.625 bit/权重, 它是 3 bit, 原件 FP4 是 4.25 bit。用户的直觉对: 同体积做到它那个数没有证据。

### 1.2 但"体积定死能力"也不全对

TECHNICAL.zh-CN.md 的位宽曲线: +3 个点 Same top ≈ 专家每权重多 0.15 bit ≈ **+11 GB**。
实际上 ② + ③ 一共 142 MB, 编程判决份 Same top 78.4 → 84.8(+6.4 pp), 按曲线折合 ≈ 23 GB 的位宽。
信息守恒没破: 我们还原的不是"全部权重信息", 是"常见输入下的输出分布"。误差可以挪到对输出不重要的方向上去, 挪的那一步不要字节, 要的是**目标(向原件对齐)和能动的参数选对**。
DeepSeek V4 原件专家本身就是 FP4, 靠的是训练时就把量化放进前向(量化感知训练), 不是事后量化。我们做不起全量训练, 但能做它的"轻量版": 量化后的位流不动, 只训量化里那些连续的小参数。

### 1.3 我们已经试过的路, 放进一张表

| | 层内闭式解(每层自己对齐) | 整模型反传(向原件蒸馏) |
|---|---|---|
| **和路由无关**(每层一份, 是输入 x 的线性函数) | 原件残差投影(10-21 判死: 层内消 9%, 端到端变差) | **现役 ③ 低秩**: +2.8 pp 后封顶 84.8 |
| **跟着路由走**(每个专家自己的参数) | ② 增益 +3.5 pp; 码本 δC / up 行增益 / 共享码本修正 都撞 ≤3% 墙 | **空白 —— 本方案** |

为什么右下角值得一试:
- 10-21 拆账: 误差 ≈101% 在专家里, "有用的误差随 token 变且近满秩, 秩 64 只吃 28%" —— 和路由无关的低秩项结构上就吃不到, 秩 128 只会过拟合(10-23 实测变差)。
- 逐专家增益的修正 `Σ_e w_e·(s_e − 1)⊙y_e` 取决于这个 token 选中了哪几个专家, 正是逐 token 变的那种(TECHNICAL §② "为什么是增益")。
- ② 是层内解的: 每层对着"原件在这一层的输出"解, 而上游层的误差在链上会累积, 层内最优 ≠ 端到端最优(放大器层内↔端到端终判: x 错位税 40×)。整模型反传直接对最终输出分布求导, 没有这笔税。
- 文献里同一招: [EfficientQAT](https://arxiv.org/abs/2407.11062) 第二段 E2E-QP 就是"量化后的整数权重冻住, 只端到端训步长(= 行增益)", 2 bit Llama-2-70B 零样本均分 69.48 对原件 72.41; [PV-Tuning](https://arxiv.org/abs/2405.14852) 在码本量化(AQLM, 和我们的 VQ-8 同一类)上做全局目标的连续参数 + 离散码号联合优化, 报 2 bit 帕累托最优。苹果 2024 端侧模型的"精度恢复 LoRA 适配器"就是我们现役 ③ 的形态; 本方案是往"训量化参数本身"再走一步。

## 2. 怎么做

### 2.1 参数与存储

- 可训: s₃[层 40][专家 384][输出通道 5120], 共 7,864 万个标量, 初值 1。生效增益 = 载荷行增益 × s₂(②) × s₃(本方案)。
- 只动 down 投影的输出通道: 这是引擎现成的覆盖槽(`g_v41_gr`), 前向 / 预填 / 解码 / 反传四条路都已经乘它, **服务端零改动**。
- 落盘: ③ 目录 `gr_Lnn.bin`, fp4x32 存 s₃−1(与 ② 同格式, 每层 1.04 MB, 40 层 **41.8 MB**); 训练中另存 f32 版(类型 1, 引擎也认)用来量"存成 fp4 丢多少"。
- 现役 ③ 低秩项: 探针阶段从 formal2 e02 读起并**冻结**, 这样增量全部归增益; 证明有用后再试两者联合训。

### 2.2 梯度怎么来(为什么几乎不花算力)

down 投影第 r 个输出通道: O[p][r] = g_eff[e][r] · (W2_e·A_p)[r], p 是 (token, 专家) 配对。
⇒ ∂L/∂s₃[e][r] = Σ_{p∈e} w_p · gy[t][r] · O[p][r] / s₃[e][r]。
O 和 gy 在现有反传里都已经在显存里(`ds4_gpu_bwd_routed_moe_tensor`: `bwd_rowdot_kernel` 刚用完、`og` 被改写成 G_O 之前), 只多一发按专家分段的归约核, 不用算任何权重形状的梯度。

### 2.3 要写的代码

| 位置 | 内容 |
|---|---|
| src/cuda/cuda_bwd_moe.inc.cu | 归约核: 每专家一段配对、每线程一通道, 确定性(不用原子加); 契约 `ds4_gpu_bwd_gain_bind(layer, grad, s3)` 绑上才算 |
| src/cuda/cuda_vq_prefill.inc.cu | `ds4_gpu_v41_gain_apply(layer, s2, s3)`: 设备上重算 g_v41_gr = s₂⊙s₃(每步 Adam 后) |
| ds4_gpu_bwd.h + src/metal/ | 契约两个新函数的 Metal 实现(同算式; 契约漂移 = 编译错误) |
| src/core/core_ptrain*.c | 配置 `train=gain`(只训增益)/ `amp` (现状)/ `amp+gain`; 分配 s₃/梯度/Adam 状态; `gradcheck` 扩到 s₃; 存盘写 gr_Lnn.bin(f32 + fp4) 与 base.fnv |
| 单测 | 有限差分梯度检查(s₃ 沿解析梯度 ±ε, 相对差 < 1e-2) |

显存: 全 40 层 s₃ + 梯度 + Adam 两份 + s₂ 副本 = 5 × 315 MB = 1.57 GB(训练余量 ~3 GB 够); 探针只训 10 层 = 0.39 GB。

### 2.4 料

不扩料(语料冻结): 用 spark 上现成的、对 1017 底座算的 FP 教师表(formal2 那 675 条, 现役 ③ e02 就是它训的)。
过拟合怎么防: 每个增益只是一个标量, 每个专家只吃到约 6/384 = 1.6% 的 token, 但一个标量对上千个观测是充分定的; 再加向 s₃=1 的 L2 拉回, 选轮照旧按留出。

## 3. 分钟级判决梯子(每一级过了才走下一级)

| 级 | 做什么 | 耗时 | 过线 |
|---|---|---|---|
| A | 有限差分梯度检查(2 层, 每层 8 个随机 s₃) | 分钟级 | 解析与差分相对差 < 1e-2 |
| B | 只训 L10~19(误差最肥的 10 层, 10-21 拆账占 32%), ③ 低秩冻结, 一个 10 分钟切片 | 10 分钟 | 留出 KL 比第 0 步(= 现役 ②+③ e02)明显下降; 降不动 = 本方案判负, 不往下走 |
| C | B 的 ckpt 过两把门(编程判决份 + wt2, 同二进制同尺对现役配对) | 门本身的时间 | 编程 Same top 对 84.77 增量 > 2 SE, wt2 只报数 |
| D | 全 40 层, 1~2 轮 | 与 formal2 同量级(那趟 67 分钟) | 同 C; 再量 fp4 落盘丢多少 |

A 不用停模型以外的任何东西; B 起要停模型子进程, **发车前报用户**。

## 4. 往后的台阶(本稿不做, 看 D 的结果)

1. gate / up 的行增益也端到端训(要在前向核里开第二个覆盖槽, 引擎改动, 再加体积, 数等形状核过再报)。
2. 每层共享码本端到端训(40 本 × 码字 × 8 维, 几乎零体积; 要算按码字聚合的权重梯度, 反传多一发核)。
3. 前三级都有收益才考虑动离散码号(PV-Tuning 那一步)。
