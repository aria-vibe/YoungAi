# 底座码字重指派(级 2 误差反馈)方案 —— 从 ISTA GSQ-RCO 借什么、怎么落地(2026-10-24)

**先说结论。** ISTA 那个仓库对我们唯一有借鉴意义的一句话是: *"2~3 bit 下标量与向量量化的差距主要是优化差距,
不是格式差距"* —— 他们把已经量好的 GGUF(同格式、同体积)拿回来, 用校准激活重新选每个权重落哪个格点, Qwen3-4B Q2_K
三项基准平均从 35.0 涨到 48.3。我们这边对应的动作是: **码本、行增益、位宽、格式、引擎、体积全不动, 只重选每 8 个权重落哪个码字**。
这条路的工具 09-21 就写好了(`gguf-tools/quantize/v41_ef.{h,cu}`, 级 2 误差反馈重指派), 从没跑过读数。
它和 10-21 "底座零语料平权, 校准量化出局" 的裁决冲突 —— **发车要用户点头**(见 §4)。

## 0. ISTA 仓库对账(只查不改, 2026-10-24)

来源: HF `ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-GGUF`, 论文 GSQ arXiv 2604.18556 / RCO arXiv 2605.00649, 代码 github IST-DASLab/GSQ、RCO。

| 项 | 他们 | 我们(现役 ①+②+③) |
|---|---|---|
| 骨架体积(不含 engram) | IQ1_M 1.75 bpw **120.7 GB** / IQ2_XXS 2.00 bpw **138.2 GB** / IQ2_XS 155.2 GB | **113.6 GB**(专家 1.5/1.625 bpw) |
| engram | IQ4_NL 110.6 GB(量化了) | 出厂原样 2×101.5 GB(不量化, 引擎直读) |
| 指标 | 只有 3 个基准(AIME25 / GPQA-D / LCB v6, 推理档 50): IQ1_M 任务均分 92.3 vs 原件 93.5(98.7%); IQ2_XXS 三项与原件相同 | 参考前向尺: judge.ids Same top 84.77% / KLD 0.230 |
| 他们报了什么 | **没有** KL、没有 top-1 一致率、没有 PPL | — |
| 校准料 | "模型自己生成的"(未给数量); 论文默认 4096 条 × 4096 token = 1680 万 token | 底座零语料; ② 拟合份 15360 |
| 量化器 | GSQ: 逐层/逐专家用 Gumbel-Softmax 松弛学"每个权重落哪个格点 + 每组缩放", 初值 GPTQ, 10 轮, Lion; Kimi-K2.5(1T MoE, 384 专家)8×H200 跑 24 小时 | Lloyd 码本 + 最近邻指派(纯权重空间) |
| 位宽分配 | RCO: 每个张量在 K 个 GGUF 类型里选一个, 预算流形上按校准 KL 的梯度走(50~200 步, Qwen3-8B 1~3.5 小时) | 最浅 14 层 13 bit, 其余 12 bit(按权重误差凸性定, 不看端到端) |

三点要说清楚:
1. **"同体积 94%" 不成立。** 他们最小的一档骨架就比我们大 7.1 GB(+6%), 推荐档大 24.6 GB(+22%); 且没有 Same top 这个数, 3 个基准的 100% 是抽样噪声级的读数(AIME25 人人 100)。
2. **真正的借鉴只有一处**: 底座的离散码字按**激活**重选, 不按权重最近邻。我们 10-21 拆账已经证明专家余量全在"码字方向误差"(增益/低秩/码本偏移五条少参数路全 ≤3%), 这正是只有重选码字才碰得到的那块肉(L10–19 整段换回原件 −31.9% KLD, 其中 2/3 在 gate/up)。
3. **GSQ 的 Gumbel 松弛本身我们一步到不了**: 他们标量格点 4~5 个, 每个权重 4~5 个 logit; 我们一个码本 4096/8192 词, 全松弛一个 8 维组要 8192 个 logit, 不可行。可行的替身是 §2 第二段"近邻 k 候选松弛"。先跑第一段(闭式一遍, 代码现成)。

## 1. 为什么现在这条路值得跑(依据, 不是感觉)

- 10-21 误差拆账(参考前向, 编程判决份 15360, 裸 0.448): 专家 ≈101% / 注意力 5.7% / 头 2.0%; L10–19 专家整段换回原件 −31.9%(−25σ), 只 gate+up −24.5%, 只 down −13.4%。
- 同一天五条"少参数修专家"路(down 逐通道 s / up 逐隐单元 t / 低秩投影 r64 / 共享码本偏移 δC / 热门专家换原件)层内全 ≤3%(扣均值口径); 结论: **有用误差是逐 token 各异、近满秩的码字噪声, 信息量 ≈ 参数量**。
- 10-23~24 ③ 后训练第二刀四个变体(加轮/换料/料×3/秩 128/专家增益)在 judge.ids 全在 84.60~84.84, 连续参数杠杆到顶(fable5 10-24)。
- ⇒ 不动 ①, 90 没有路。动 ① 又不加体积, 唯一能碰到码字方向的就是**重选索引**。

## 2. 方案三段(等体积 113.56 GB, 引擎零改动)

### 第一段 · 级 2 误差反馈重指派(代码现成, 本方案要发的车)

GPTQ/GPTVQ 同式: 码本 C 与行增益 g 按级 1(现役 Lloyd)定死; 每个专家每个矩阵, 8 列一组从左到右, 组内按 H⁻¹ 的 Cholesky 对角加权选码字, 本组的量化误差按 H 传给右边还没量化的列(128 列懒分块)。
- H(x 侧, gate/up 共用) = X_eᵀdiag(rw²)X_e/Σrw² + β·E_layer[xxᵀ] + δ·mean(diag)·I; β ∈ {0.1, 1} 每专家按 val 行输出误差二选一; δ = 1%。
- H(h 侧, down) = hᵀdiag(rw²)h/Σrw², h 在**已重指派**的 Ŵ1/Ŵ3 上算(= 部署时 down 真吃的输入)。
- 名下 < 8 行的专家不做(保级 1 指派)。
- 为什么锚层级 Gram: 校准 8192 token 时每专家中位几十行, L39 中位 5 行, X_e 张不开 5120 维; 层级 8192 行补方向, β 定话语权。这是本段最可能的瓶颈(§3 的层账会直接显出来)。

入口: `v41_quantize … --calib <取料目录> --calib-alpha 0 --calib-ef 0.1,1`。`--calib-alpha 0` 让级 1 列权退回平权 = 现役零语料同一条路(§3 P1 会用逐字节比对证明), 级 2 是唯一变量。

### 第二段 · 近邻 k 候选的 Gumbel 松弛(GSQ 的替身, 第一段读正后才写)

每个 8 维组只在它的 k=8 个最近码字(按 H 加权距离)里松弛: 8 个 logit/组, 逐专家对**出厂 FP 专家输出**(gate/up/down 三个一起, GSQ 的 block-wise, 论文 Table 15: 只按线性层 57.7 → 整块 62.0 → 分阶段 65.5)做 10 轮 Lion, 温度 2 → 0.05 线性。
账: 一个专家 3 个矩阵 ≈ 390 万组 × 8 logit × 4 B = 125 MB; 一层 384 专家顺序做, 显存不是问题。算力: 每专家每轮 = 行数 × 3 × (5120×2048×2) × 3(前向+反向) FLOP; 校准 8192 token 时每专家 ~128 行, 10 轮 ≈ 2.4 TFLOP/专家, 一层 0.9 PFLOP —— 在 GB10 上是分钟级, **瓶颈不是算力是行数**(128 行拟 390 万组的离散选择会过拟合, GSQ 用 1680 万 token)。
所以第二段的前置是**校准料加厚**(§4 第二个审批点), 不是写码。

### 第三段 · 第 13 位的层分配按端到端损失重定(RCO 的借鉴, 等体积)

现役 13 bit 给了最浅 14 层(L00–13), 依据是**权重误差**的凸性; 10-21 端到端拆账说专家最肥的是 L10–19。RCO 的点就是按**任务损失**分配。
等体积探针: 把 13 位从 L00–03 挪到 L16–19(各 4 层, 体积逐字节相同), 8 层重量化 + 一把尺。第一段读数出来后再定要不要跑(第一段改变了各层的误差形状, 分配要在新底座上定)。

## 3. 第一段的落地步骤(探针 → 全量), 每步的尺与停车线

探针范围选 **L10–19**(10 层), 不是 1 层: 这段的天花板精确已知(整段换回原件 −31.9% KLD, 配对 σ ≈ 1%), 一层的天花板约 −3%, 只有 1 层读数落在 1~3σ 分不清; 10 层把读数拉到 ≥ 5σ 才算判决。
全部命令都在 `gguf-tools/scripts/v41_fincal_chain_spark.sh --probe 10:20`(10-24 参数化: `--hf/--base/--base-dir/--ids/--cal/--tag/--recipe`), 用 `with_model_stopped_spark.sh` 包着跑(取料与判决都要机器空出来)。

| 步 | 做什么 | 尺 / 判读 | 停车线 |
|---|---|---|---|
| P0 取料 | `v41_amp_run <现役 1017 ①> <hf> vqhalf_q.ids 8192 <CAL> --dump-calib`: 裸 ① 上一趟八域量化份, 40 层同趟落 calib_Lnn.bin(3.4 GB) | 自检: 每层 top12 通道能量占比 / 名下行数(最少/中位/<8 行专家数) | 行数收不齐 = 钩子错位, 文件全删 |
| P1 审计 | L10–19 用 `--calib CAL --calib-alpha 0`(无 EF)重量化, 逐分片 `cmp` 现役分片 | **必须逐字节同** ⇒ 级 2 是唯一变量; 不同 ⇒ 级 1 带 calib 的路与零语料路有差, 判决改用 P1 产物当基线臂 | 不停车, 只改基线臂 |
| P2 级 2 | 同配方 + `--calib-ef 0.1,1`, 产物目录 `<tag>-probe-10-20-lv2/`(其余 30 层 + common 软链现役) | 层账: `级 2 做 N / 跳过 M; β=0.1×a β=1×b; val 输出误差 级2÷级1 均值 r` | 任一层 r ≥ 1.0 = 级 2 没降层内误差, 机制有 bug, 停 |
| P3 判决 | `v41_judge.sh judge.ids 15360 --hf <1017> file:<基线> file:<lv2>` + wt2 512 守门 | 五指标两臂同趟同尺; `judge_rows_pair.sh` 逐位配对(普遍变好 vs 随机搅动, 十分位) | 判决份 KLD 不降或 wt2 退 > 配对 2σ = 判负 |

| 全量(★点头★) | 40 层 `--calib-ef`, common 软链现役; 转 GGUF(体积逐字节同 113,556,639,424 B 预期, 只换索引位); 引擎对拍 wt2 512 KL ≤ 0.07; ② 在新 ① 上重解(grrb 链), ③ 重训 | 部署态 judge.ids 五指标 vs 现役 84.77 | — |

读数怎么换算到 Same top: 第一刀的经验是 KLD 每降 10% ≈ Same top +1 pp(0.318 → 0.230 对应 82.0 → 84.8)。专家段整体天花板是 KLD 几乎全部; 级 2 若全模型吃到 f=1/3 ⇒ 裸 KLD 0.448 → ≈0.30, 叠 ②③ 后估 87~88。**90 不在这一段的射程里, 要第二段**; 这是估算不是判决, 以 P3 的读数为准。

## 4. 与既有裁决的冲突 —— 两个审批点, 不点头不发车

1. **语料进 ①**(09-20 "量化基座永远不要动"; 10-21 "校准量化会像专家裁剪, 违背初衷"): 本方案就是校准量化。与 09-21 判负的级 1 不同的两点: ①列权(级 1)修的是幅度、与 ② 增益重叠, 级 2 修的是码字方向、② 碰不到; ②09-21 用的是金融单域料(wt2 −2.15 pp 域税), 这次用八域量化份 vqhalf_q(academic/prose/code/euro/cyrillic/math/arabic/cjk 各 1024), 守门尺 wt2 照跑, 退就判负。
   **域税的真风险仍在**: GPTQ 系在校准域外的退步是文献共识, 所以 P3 两把尺缺一不可。
2. **校准料加厚**(08-06 "校准语料冻结"): 第一段用现成 8192 不动; 第二段(Gumbel)需要加厚(≥16×), 单独报批。
