# 还原侧车与扩展件: 按"干什么"重划 ② 和 ③(2026-10-24 用户定, 方案稿, 未发车)

**用户定义(10-24 下午)**: 侧车 = 对原件的**还原**; 后训练 = 能力的**扩展**(扩展也可以扩展原件已有的能力, 但它的目标不是原件)。
一句话: 以后判"这东西该进哪一件", 只问它的靶是不是原件的分布 —— 是, 就是侧车; 不是, 就是扩展件。工具(闭式解 / 梯度蒸馏)不再是分界。

## 0. 现在错在哪(证据)

| 现状 | 问题 |
|---|---|
| ② = 闭式解出来的(增益 + 路由偏置), ③ = 梯度训出来的(低秩放大器) —— 按**工具**分 | 10-22 的"③"(fp-formal2: 向 FP 蒸馏, 修问号 / EOS / `</think>`)靶是原件分布、尺是 FP 锚, 按定义是还原, 却叫后训练 |
| 10-20 "think 放进侧车判负"(编程窗套思考模板喂闭式解算器: 判决份退、wt2 退、收口位 Σp 掉一半) | 不是 think 不属于侧车, 是闭式增益解算器对全部位置做平均最小二乘, 看不见几个决策位; 决策位只有向原件蒸馏(梯度对末端 logits 做 KL)碰得到 |
| ③ 绑死在训练时挂着的 ② 上(引擎 10-24 17:22 实撞: "后训练件是解在另一个反修态上的(指纹 a0e290…/69 层, 现挂 afc955…/70 层)", 拒挂) | 一个还原目标被拆成两件、两条链、两份指纹, 换 ② 就要重训 ③ |
| 一域一份 ②(编程 / 金融 / 法 / 医 / 科 / 今天的图形) | 09-28 量过: 本域 +3.3~3.7 pp 里**专属份额只 0.8~1.0 pp**; 今天图形 ② 对编程 ② 在图形判决份只多 0.6 pp。业务上没有按域切换的场景(用户 10-24) |

## 1. 新形态

```
①  底座 GGUF(零语料, 不动)
②  还原侧车(一份, 不按域):   段 A 闭式: 逐专家 down 逐通道增益 gr_Lnn.bin + 路由偏置 rb_Lnn.bin   ← 混合拟合份, 编程最重
                              段 B 蒸馏: 低秩放大器 amp_Lnn.bin(秩 64)向 FP 教师表蒸馏, 料含决策位(官方思考轨迹尾段/中段、整篇文档)
                              同一目录, 一份 manifest, 一个指纹; 尺全是 FP 锚
③  扩展件(可零份、可多份): 在 ② 之上训, 靶是任务(交易 / 助理行为 / 用户纠正), 尺是任务尺, ★永不用 FP KL 判★
```

- **引擎不改**: 现在就是 ② 的增益与 ③ 的增益相乘、低秩按秩拼接(`core_v41_amp.c`); 段 B 的 amp_Lnn.bin 放进侧车目录, 加载路径同 `--posttrain`, 指纹闸改成"段 B 对段 A 自己"(同一目录内自洽)。
- **工作台**: 聊天页下拉只剩一份还原侧车(以后如果某域专属份额 > 1 pp 再单列); "后训练"开关改名"扩展件", 只管 ③; 训练页的"向原件蒸馏"归到侧车链里。
- **发布**: HF 上的 ③ `posttrain-code-20261022` 按定义是还原件, 下一版随侧车目录一起发, 不再单列。

## 2. 还原侧车的链(两段, 一条命令)

### 段 A · 闭式(现有 grrb 链, 只换拟合份)

拟合份 = 混合, 总 15360 位(解算器的 held-out 规则要每域 ≥ 4 窗, 窗 128):

| 域 | 来源(都已有, 零新分词) | 配额(窗 / 位) | 为什么 |
|---|---|---|---|
| 编程(30 语言) | gguf/go-onebit/code/fit.ids | 96 窗 / 12288(80%) | 用户: 编程最重 |
| 数学 | 八域份 vqhalf_a / vqhalf_q 的 math 子域 | 12 窗 / 1536(10%) | 用户 10-24: 编程跟数学相关; 现有通用份里 math 只占 1/8, 单给配额 |
| 图形代码 | gguf/go-onebit/graphics/fit.ids(10-24 官方 API 原件生成的 57 篇画图程序, 坐标密集) | 12 窗 / 1536(10%) | 10-24 量过画图页面 58% 的 KL 在坐标区, 编程份里没有坐标 —— 作为编程的子域进, 不单列域 |

★配额的账(10-24 晚)★: 第一版是 8 域混合(编程 48 / 图形 12 / 数学 12 / 金法医科各 9 / 通用 12), 段 A 解完编程判决份 Same top 81.51% / KLD 0.3277,
输现役编程 ② 的 81.90% / 0.3188 —— 用户判"指标下降说明不对", 改成编程 80% + 数学 10% + 图形 10%, 金法医科/通用不再掺。
两级泄题指纹(整窗 + 16-gram 对全部判决份)不变; 候选里剔掉的窗记在 fit.ids.manifest.txt。

实现: `amp_campaign.sh --profile restore`, `stage_idsmix` 按配额从各域现成 fit.ids 等距抽窗(不重切, 判决份不动), 布局文件写每域起止。
判决份不混: 各域判决份各自保留, 尺见 §3。

★解算器的过程指标(10-24 晚用户令"反修的过程指标换成 Same top / KLD / RMS, 之前这么改过")★: 增益路每层的赢家不再按层内 held-out 能量挽回率选,
而是 10-21 那套端到端择优(`gguf-tools/amp/v41_e2e_select.inc.c`, 10-22 回退进 stash 后今晚取回主树): 层内 val 前 2 个 λ 候选逐个挂上跑全前向,
在拟合份 val 行(3840 位, 解算从没见过)上对拟合份自己的 FP 教师锚算判决器五指标里的三把 —— Same top / KLD / RMS Δp(top-32 联合窗) ——
三项全优者赢; 没有全优者先否决 Same top 比基线退超 2σ(σ = √不一致行数)的候选, 剩下 KLD 最低者赢, KLD 差在趟间噪声内比 RMS Δp; 基线(不挂增益)也参赛。
Δb 只由层内闸定, 端到端不撤(10-21 诊断: 逐层裁 Δb 会错杀"一串层合起来才赚")。与 10-21 版的唯一不同: 第三把尺由 NLL 换成 RMS Δp。
代价: 每层多 2~3 趟拟合份全前向。先 `--layers 2` 探针验机制(产物带 -probe, 不进对照), 再 40 层。

### 段 B · 蒸馏(现有 ③ 链, 挂在段 A 上, 产物进同一目录)

- 料 = 10-22 formal2 配方(整篇文档 ≤1024 位 + 官方思考轨迹尾段 + 中段负样本), 文档份按段 A 同样的域配额; 教师 = FP top-64 表(按序列内容复用, 已有的不重算)。
- 训练器不改(`./ds4 --ptrain … --base-amp <段 A 目录>`), 只把落盘目标改到侧车目录、指纹按段 A 算; 选轮规则照旧(留出最低且收口不少于部署态)。
- 决策位尺(think_close_probe_spark.sh)进段 B 的判决, 和 10-22 一样对标 FP 量级。
- **料先过泄题审计**(10-24 晚 `leak_audit.py` 实撞): formal2_1022 的 612 条里 47 条与法律 / 科研判决份共享 16-gram(docend 整篇文档料从本地法律 / 科研语料取的, 和 09-27 切判决份的是同一池子: 欧盟条例 156 个片段、中文论文摘要 129 个), 对编程判决份零命中。
  以前只有编程尺时这不算泄题, 现在法医科是尺就是。段 B 的料 = `restore_clean/formal2_1022.clean.jsonl`(命中任一判决份的整条剔掉), 保持料 hold.jsonl 零命中。

### 侧车就是一个目录, 没有"决策位目录"(用户 10-24 两次定: "决策位文件合并到侧车里面" / "现在没有决策单独目录了, 都定义能力的还原")

```
<侧车目录>/   ← 唯一产物, 名 <①名>-grrb-restore_fit_n15360-engine
  gr_Lnn.bin   rb_Lnn.bin        ← 段 A 解出来的
  amp_Lnn.bin                    ← 段 B 训出来、选中轮的低秩项, 直接放同一层, 不分子目录
  manifest.txt                   ← 一份账: 段 A 的层账 + 段 B 来自哪趟哪轮、留出损失、决策位读数
```
两段是**同一个产物的两道工序**, 不是两件东西: 装载、判决、发布、工作台下拉都只认这个目录。
- **引擎不用改**(核过 `core_v41_amp.c:292`): 挂 `--zchain DIR` 时本来就读 DIR 自己的 amp_Lnn.bin(k2), 再按秩拼上 `--posttrain` 目录的(k3) —— 侧车目录里放了 amp 就自动装, 零改动。`--posttrain` 只留给扩展件 ③(靶不是原件的那种), 它的指纹闸照旧对侧车目录的 gr 核; 还原件内部不需要指纹 —— 同一目录就是同一产物。
- **训练器**: 段 B 挂 `--zchain <侧车>` 训(此时目录里还没有 amp, 不会自己叠自己), ckpt 照旧落在训练目录; 链选轮后把 amp_Lnn.bin 拷进侧车目录, manifest 追加段 B 一行。再训一次段 B = 先把目录里的 amp 挪走再训(不许叠加训练, 和 core_ptrain_bwd.c 的"换了底座不许叠加"同一条纪律)。
- **判决**: `engine:<gguf>:<侧车>` 一臂 = 整个还原件; 段 C 的四臂变三臂: 裸 / 现役对(编程 ② + ③, 用 `::` 挂, 它是老形态) / 还原侧车。
- **工作台**: 下拉一份还原侧车; "后训练"开关改名"扩展件", 只管 `--posttrain`; serve_pick.txt 第 3/4 行只给扩展件。
- **发布**: 侧车目录整个上 HF, ③ 单列条目退役。
- 不动的: 训练器落盘格式、低秩按秩拼接、gr/rb 格式。

## 4. 扩展件(③)的规矩

- 靶不是原件 ⇒ **不许用 FP 锚判**; 尺 = 任务结果(交易: 10-02 "评③只看技术指标"; 助理: 校验相 / 记分卡那类)。
- 在还原侧车之上训, 指纹绑还原侧车; 料是任务料(复盘 / 用户纠正 / 工具轨迹), 不是整篇文档。
- 训完不自动挂(10-10 用户令照旧)。
- 现在盘上没有一份真正的扩展件: 10-22 ③ 归还原; 09-19 复审判死的交易 ③ 系列是扩展件的失败先例(教师不是原件、尺是收盘价), 它们的教训(LLM 事后叙事 / 提示词路禁)继续适用。
