# think_close.md — 用 ③ 后训练修"思考不收口 / 自问问号", 顺带量它能推多少 Same top(2026-10-22; 方案稿, 未动代码, 发车待批)

> 读者假设第一次接触。带日期的数都是盘上实测(出处 fable5.md 同日段); 没量的标【无数据·待实测】。
> ③(用户数据训出来的低秩放大器)的机制 —— 料格式 / 教师 / 损失核 / 选轮 —— 见 docs/posttrain.md, 这里不重复, 只写这次改什么、为什么、怎么判。

## 0. 先答三个问题

1. **思考能不能正常结束** —— 一半以上能, 剩下的 ③ 治不了。
   不收口分两型(都是拿 FP 原件对同一条序列逐位重打出来的, 不是猜):
   - **还原型**: 模型想停, 量化把 `</think>` 压掉。s1(09-30) FP 22%~49% → 量化 1%~6%(4~22 倍); r316(10-17) 全程 Σp FP 0.968 → 量化 0.345(2.8 倍); 整篇文档结尾 EOS(09-30, 25 篇) FP 0.088 → 0.011(8 倍)。
     **权重能修**: 现役金融侧车的料里一个结尾都没有, 顺带把 EOS 拉回 2 倍(0.011 → 0.023)。
   - **行为型**: 鹈鹕(10-20, 1017 底座) FP 自己 Σp 0.049, 量化 0.034 —— 原件也不想停。向原件还原对它无效, 只能靠已上线的死环检测器兜底(或用户另定要不要"改行为", 见 §7)。
   量过的三条里两条是还原型。**1017 底座上还原型压了几倍还没量**(09-30/10-17 的数都是 v3 底座), 第 0 步补。
2. **问号** —— 跟收口是同一个病, 今天(10-22)多了两个数。
   近 10 天 636 条助理回答: 正文每千字 1.2 个问号(基本是真提问), 思考段 4.89 个, 全是英文自问("cos(274)=?" / "maybe?")。
   FP 原件在量化模型吐 '?'(id 33) 的位置上有多认同: 鹈鹕 1020(1017 原件锚, 32k 生成位) 349 处, FP 几何均值 p 0.107, **argmax 也是 '?' 的只有 36%**; r316(v3 原件锚) 60 处, 43%。一般 token 的 FP argmax 命中率是 57%~84%(10-20 逐桶)。
   ⇒ '?' 被量化过采了。09-30 量到的"尾巴 +3.7 nat 变平、决策位 −1.2~−1.8 nat"就是这两面: 锐的决策磨钝(不收口), 犹疑的尾巴变厚(自问)。
   局限: 轨迹是量化模型自己采的, 这个数偏向学生; 学生侧同位 p 要第 0 步重打(`stu_faith_1016_*` 学生锚盘上已不在, 只剩文本日志)。
3. **Same top 推到 90** —— ③ 这条路做不到, 不顺着说。
   账(10-21 误差拆账 + 热门专家扫描, 估算): 36 MB ② 侧车 78.40 → 81.9(+3.5 pp); 再加 464 MB 残差码 ≈ +1 pp; 85% 要 1.7~4.6 GB; 90% 要 11~45 GB(热门专家换出厂原件)。骨架(注意力/头/共享)全修也只 +1 pp。
   ③ 是 40 层 × 秩 64 的低秩项(105 MB f32), 容量级别与 ② 相当 ⇒ 对 Same top 的贡献按账 +1~2 pp 封顶【待实测, 本方案顺带量】。要 90 得走热门专家原件 / 升位那条, 另立方案。
   更要紧的: **Same top 不是收口的尺**。判决份 15360 位里决策位只有几十个, 决策位那 1.5 nat 的 KL 项在逐位平权的 Same top 里几乎看不见 —— 10-17 的 ③ 把留出压 46%、行为纹丝不动, 就是这个盲区。这次的门是决策位比 + 真实请求收口率, Same top / wt2 只做"不退"门。

## 1. 为什么现在的 ③ 修不了这个, 要改三处

| 现在 | 问题 | 改成 |
|---|---|---|
| 教师 = 部署态自己(①+②, 上下文蒸馏) | 教师自己就被压到 1%~6%, 学生学不到 22%~49% | **教师 = FP 原件**(`v41_teacher.py` 参考前向, 与判决尺同一条路) |
| 料 = 128~512 窗 / 问答 / 整段 text, 从没有一个 `</think>` 或 EOS 进过 KL | 决策位不在料里, 梯度不可能往那走 | **带结尾的整篇 + 带收口的思考轨迹尾段**, 每条 ≤1000 token 把 `</think>` + 正文 + EOS 包住 |
| 尺 = 留出 KL + 贪心收口探针(不思考渲染) | 留出看不见决策位; 贪心配思考必进环(10-19); 思考料没有问句, 探针 0 题 | **决策位几何均值比**(teacher-forced, 秒级) + **真实请求采样收口率**(默认配方, 不设上限) |

不动的: ③ 形态(每层 MoE 输出 `y += xn·B·A`)、maxlen 1024、L0-39、K=64、lr 2e-4、hold 保持料、wt2 配对 SE。
待定: 训练起点 = ①+现役编程侧车 还是裸 ①(spark serve_pick 10-21 起是 base + none), 要与部署时挂的一致, 用户定。

## 2. 料: 全部来自原件, 量化模型零参与

| 份 | 内容 | 量 | 来源 / 待批 |
|---|---|---|---|
| A 整篇结尾 | 13 子域整篇文档 ≤1000 token, 带真 EOS | ~300 篇 ≈ 300k 位 | `docend_corpus_build.sh 25 300 1000`(现有脚本只改参数; 现在 25 篇 12.5k 位), 料在 `gguf-tools/data/corpus/{law,med,sci,code}`, 不碰反修校准集 |
| B 收口轨迹尾段 | 原件自己的思考轨迹, 只取末尾: 思考末段 + `</think>` + 正文 + EOS, ≤1000 token | ~200 条 ≈ 200k 位 | **官方 API**(`reasoning_content`), 题 = 公开编程题(HumanEval / LCB)~100 + 通用与决策题 ~100(用户给 3~5 条真实请求去隐私 + 公开题)。★外部资源待批: api.deepseek.com 按量计费, "输出可否用于训练"条款待核★。备选 OpenThoughts-114k(Apache-2.0, R1 轨迹): 风格不是 V4.1 的, FP 在它的收口位给多少没量, 排第二 |
| C 保持料 | hold.jsonl 63 题 | 现有 | 不动 |
| 留出 | A / B 各 1/5(FNV 五取一, 现有) | | |

- **为什么 B 不算"自吐"**: 09-30 用户判"量化模型自吐当料是本末倒置" —— 这里轨迹和教师都是原件, 量化模型全程不参与。
- **为什么只取尾段**: maxlen 1024 是硬顶(训练缓冲 f32, 10-17 实测 1024 行 5.1 GB, 开训后可用内存 3.2~3.4 GB, 2048 必撞看门狗)。"该收口了"的信号在局部(前几百 token 的"综上 / Let me write / Final"), 窗内够; 整条轨迹 5k~30k 装不进。
- **尾段怎么切**: 采集脚本按字符从末尾截(保守 2500 字符 ≈ ≤1000 token, 2.4~3 字符/token), 装料仍走现有"超长按 token 切段、EOS 只跟末段"。不加新字段(10-10: 料只有 messages / text 两种行)。

## 3. 教师: FP top-K 导进 ③ 的教师表

- 现在的 FP 教师锚是全 logits(`<i32 S><i32 V><f32>`, 517 KB/位; 43.8k 位 22.7 GB)。spark 盘只剩 123 GB(3.7 T 用了 97%)⇒ 500k 位 258 GB 落不下。
- 改: `v41_teacher.py` 加 top-K 输出(K=64 的 id / p + 榜外余量, 512 B/位, 500k 位 256 MB), Python 侧只做"取前 64 个落盘"; C 侧 `pt_teacher` 新来源 `teacher=fp:<锚>`, 按现有 PTK2 记录格式写 `.teacher.bin`, 键里的 ② 指纹换成 FP 标识(不换的话换侧车重训会命中错教师, 10-10 踩过), 余量算法同 `PT_TEACHER_VER`。缺题直接报错停车, 不回退到部署态教师。
- 成本口径(实测速率, 不是预估): FP 教师一趟 1,622~2,100 s / 12k~15k 位(10-21 / 09-30), 大头是流式读原件, 位数影响小; 训练 72 行/s(10-17: 57.9k 行 809 s, L0-39 batch 4 maxlen 1024)。

## 4. 判决: 四把尺各答一个问题, 都是分钟级

| 问题 | 尺 | 读什么 | 门 |
|---|---|---|---|
| 决策位修回来了没 | teacher-forced 重打分(停模型 ≤5 min): docend 25 个 EOS 位(1017 锚重算)+ pelican_1020(1017 锚已有)+ r316 入环前段(1017 锚重算) | `</think>` / EOS 位上 学生 p 对 FP p 的几何均值比(`bugmd_ids_tools.py tokprobe`) | 现 1/8~1/4 → **≥ 1/2**; 没动 ⇒ 停车审计, 不加旋钮 |
| 真会不会停 | 生产服务采样: 10 条真实请求(鹈鹕 / HumanEval-129 / r3 + 用户 3~5 条决策题)× 3 趟, 默认配方(温 1 / top_p 1 / min_p 0.02), **不传 -n**(判"不停"前先不设上限跑完, 地板 128k; `think_stop_probe.sh` / `asst_send_probe.sh`) | 收口率 / 思考 token 数 / 思考段 '?' 每千 token / 检测器 forced 次数 | ③ 挂 vs 卸: 收口率不降、'?' 密度降; 还原型那几条必须有改善 |
| 问号过采降了没 | 同一条轨迹 `tokprobe … 33`: FP vs ③ 学生 | '?' 位几何均值比 + 其余位置 p('?') 均值(FP 2.84e-3) | 向 FP 靠 |
| 通用退没退 | 编程判决份五指标 + wt2 512, ②态 vs ②+③态 配对 SE(`v41_judge.sh … engine:GG:②:③`) | KLD / Same top 增量 ± SE | 超 3 SE 真退否决; Same top 只报增量(回答 §0.3) |

选轮(`src/model/model_train_pick.c`)对这类料: 贪心收口探针无题可抽 ⇒ 改成"留出 KL 低于第 0 步 + 决策位比不低于第 0 步"; messages 料的老规则(10-11 用户定)不动。

## 5. 梯子: 第一步必须一小时内见数

0. **第 0 步(不训练, 停模型一次)**: 1017 底座 + 现役侧车上重打 docend / r316 / pelican_1020 的学生锚, 加 docend / r316 的 1017 FP 锚 → 决策位比、'?' 比的**现状数**。没这一步, 后面"修了多少"没基线。
   若 1017 已经不压(比 ≈ 1)⇒ 病全是行为型, 本方案停, 改方向。
1. **探针趟**: 料 = docend 25 篇 + 收口尾段 20 条(≈ 27k 位), FP 教师一趟, 训 3 轮, 留出 5 篇 + 4 条上读决策位比。硬阈值: 留出决策位比对第 0 步**翻倍**; 否则停车查三处: 教师导入对不对、`</think>` 分词是不是 128822、窗起点。
2. **正式趟**: A 300 + B 200, 3~6 轮, §4 四把尺全过。
3. **兑现差才做 v2**(teacher-forced 比好、生产采样却不收口): 前缀预填 + 只在尾窗反传 —— 教师缓存已有前缀快照机制(`PT_TAIL` / `PT_TROWS`), 学生侧加"前缀只前向不存档"的合批模式, 让窗样本的输入分布与生产一致。

发车(第 0 步起)要用户批; 改码 / 编译 / 同步 spark 不用。
