# "编程里的数学 / 美术成分没覆盖到" —— 先量再补: 图形代码域的尺与侧车(2026-10-24)

用户判断(10-24): 编程看上去是编程, 做出来的东西跟数学、美术等学科相关; 后训练语料可能没覆盖这些场景, 激活差; 鹈鹕能出页面但效果一般。
本稿做三件事: ①用现成读数先验一遍这个判断里能验的部分(§1, 已量); ②给这个判断造一把能量它的尺(§2); ③尺上有差再补料, 补的是 ② 侧车不是 ③(§3, 为什么见 §3)。

## 1. 已量: 损失按 token 类分桶(零成本, `gguf-tools/scripts/judge_rows_tokclass.py`, 2026-10-24)

现成 `anchor_metrics --row-out` 的逐位置读数, 按**目标 token 的类**分桶(digit = 含数字 / word = 含字母 / punct / space / other)。
编程判决份 judge.ids 15360 位, 三臂 ① 裸底座 / ①② 挂编程侧车 / ①②③ 再挂后训练(现役):

| 类 | 占比 | ① KLD / Same | ①② KLD / Same | ①②③ KLD / Same | ③ 对 ① ΔKLD |
|---|---|---|---|---|---|
| digit | 4.4% | 0.423 / 77.4% | 0.303 / 79.5% | 0.236 / 81.3% | −44% |
| word | 57.4% | 0.508 / 75.5% | 0.372 / 79.3% | 0.274 / 82.5% | −46% |
| punct | 13.1% | 0.362 / 84.3% | 0.250 / 86.7% | 0.169 / 89.2% | −53% |
| space | 9.8% | 0.298 / 84.7% | 0.192 / 87.7% | 0.131 / 90.0% | −56% |
| all | 100% | 0.446 / 78.4% | 0.319 / 81.8% | 0.230 / 84.8% | −48% |

鹈鹕轨迹(10-20 量化模型自己生成的 32,469 位, FP 原件锚, 11,358 位提示之后):

| 类 | 占比 | ① KLD / Same | ①②③ KLD / Same | ③ 对 ① ΔKLD |
|---|---|---|---|---|
| digit | 13.8% | 0.208 / 83.3% | 0.141 / 86.1% | **−32%** |
| word | 53.0% | 0.289 / 74.6% | 0.161 / 81.3% | −44% |
| punct | 19.2% | 0.150 / 86.5% | 0.075 / 90.9% | −50% |
| all | 100% | 0.238 / 79.4% | 0.133 / 84.9% | −44% |

读法:
- **损失不是数字专属**。数字位的 Same top 不比标识符差(81.3 vs 82.5; 鹈鹕 86.1 vs 81.3), 09-20 旧底座"数字位 51.5% vs 65.4%"的坑在 1017 + ②③ 上已经填平。"坐标数字写不准"不是鹈鹕简陋的主因。
- **最大的一桶是 word**(标识符 / 关键词 / 英文词, 57% 的位置, Same 最低)。这是"选哪个词 / 哪个属性 / 哪个形状"的位置 —— 用户说的"学科知识", 要是真丢了, 丢在这里。
- 鹈鹕上 ③ 对数字位帮得最少(−32% 对别类 −44~−50%): 现役 ③ 的料(整篇代码文件 + 官方思考轨迹)里坐标数字少, 这一点和"料没覆盖"相符, 但它的绝对损失已经是各类里偏低的。
- 这把尺量不到"学科知识": 它只知道 token 的字面类, 不知道这个位置是在"决定鹈鹕的嘴画成什么形状"。所以要 §2 那把尺。

## 2. 给这个判断造一把尺: 图形代码域判决份(部署态格式)

**官方原件的鹈鹕(10-23 dsh 对照, Mac `gguf/dsh/runs/official-pel{1,2}/ws/index.html`, 48,064 / 40,300 B)就是最硬的靶**: 这是原件在同一句请求下真写出来的东西, 把它 teacher-forced 过 FP 锚和 ①②③ 三臂, 逐位置读数按**内容区**分桶(SVG `<path d=` 坐标串 / 标签与属性名 / CSS / JS 动画逻辑 / 注释与文字), 量化在哪一区掉得最多, 直接回答"美术成分是不是被量化吃掉了"。
两份文件 ≈ 2 × 12k token, 教师锚一趟, 三个学生臂走 `v41_judge.sh … file:` / `engine::`, 逐位分桶用 §1 的脚本加 `--regions`(按字符区间给类, 需加 ~30 行)。

**再造一份 30 篇的图形代码判决份**(与 judge.ids 同口径 30 × 512, 部署态 BOS + 文件头): 本地语料里图形类太薄(html 5 篇 / js 7 篇含 SVG 或 canvas, tex 14 篇 TikZ), 不够 30 篇 + 拟合份。
来源 = 官方 API 原件生成(`think_trace_collect.py collect` 复用, 只换题单): 60 道题 × 6 类(SVG 插画 / canvas 动画 / p5.js / three.js / TikZ / matplotlib), 题单两半互斥: 30 篇进判决份、其余进拟合份, 16-gram 零共享核对(judge_doc_ids.py 同一套)。
官方 API 的产出是原件的分布, 不是本地量化模型自吐(09-30 铁律管的是后者); 10-22 的思考轨迹料就是这么采的。**要花 API 钱(≈ 60 次调用), 发车前报批。**

门(§2 出数后再定下一步): 图形判决份上 ①②③ 的 Same top 比 judge.ids 的 84.77 **低 ≥ 3 pp** ⇒ 域差是真的, 进 §3; 差 < 1.5 pp ⇒ 判断不成立(损失是通用的, 不是覆盖问题), 到此为止, 鹈鹕简陋归 10-23 的另一半原因(模型思考里自己砍: "Keep it simple", 行为不是知识)。

## 3. 尺上有差才补, 补的是 ② 不是 ③

- **② 按域一份是验过的杠杆**: 09-27 法律 / 医疗 / 科研三个新域, 本域 Same top +3.3~3.7 pp, wt2 不退。图形代码域照同一条链(`v41_sidecars_all_spark.sh` 的 grrb 链, 拟合份 = §2 的官方生成拟合份 15360 位), 判决在图形判决份 + judge.ids 守门 + wt2 守门。
- **③ 为什么不先上**: 本周四个变体换料三次, judge.ids 全在 84.60~84.84(docs/posttrain_gain.md 结论: 第二刀上限 ≈ −2.5% KLD); 10-17 鹈鹕 SVG 料的 ③ 留出 −46% 但生成一笔不动("起笔先验没动")。料的内容进 ③ 只改变拿的是哪 2.5%。② 挂新域的历史读数比 ③ 大一个量级。
- **终判不是五指标, 是鹈鹕本身**: 同一句请求, 同一个 harness(tests/asst/dsh_compare.sh 本地臂), 现役对 vs 新 ② 各跑 3 趟, 看文件大小 / SVG 元素数 / 截图; 官方原件两趟 40~48 KB 是上限参照。
- **预期带(说在前面)**: 本域 +3~4 pp 是历史读数, 不是 90; 鹈鹕"造型简陋"的另一半在模型思考里自己砍需求, ② 不治那个。
